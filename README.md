## 🎯 About

This is a **reading library**, not a code project. Each entry is an e-book (mostly PDF, with a few other formats) on a technology topic. The collection leans toward:

- **Cybersecurity & ethical hacking** — from beginner to advanced
- **Penetration testing** — Kali Linux, Metasploit, web app testing
- **Linux internals & administration** — kernel, system programming, sysadmin
- **Networking** — TCP/IP, routing, protocols, packet analysis
- **DevOps-adjacent topics** — the systems, security, and infrastructure foundations that DevOps builds on

The goal is simple: **keep good learning material free and easy to find**, and let the community keep it growing.

## 📖 How to Use This Library

1. Browse the [catalog](#-book-catalog) below and click any title to open the file on GitHub.
2. Use the **Download** button on the file page to save it locally, or clone the whole repository:
   ```bash
   git clone https://github.com/tdlmatias/Techie_Books.git
   ```
3. A few files are stored compressed — for example `.pdf.gz`. Decompress before reading:
   ```bash
   gunzip "Vickie Li - Bug Bounty Bootcamp_ The Guide to Finding and Reporting Web Vulnerabilities-No Starch Press (2021).pdf.gz"
   ```

> 💡 **Tip:** GitHub renders PDFs directly in the browser, so you can preview most books before downloading.

## 🤝 Contributing — Enrich This Library

**Everyone is welcome to contribute.** Whether you have one great book or a whole shelf, your addition helps thousands of learners who follow this repository. You don't need to be an expert — a good, relevant, freely shareable book is all it takes.

### Ways to help

- 📕 **Add a book** on any covered topic (or a well-justified new one).
- 🗂️ **Improve organization** — better categories, cleaner filenames, fixed links.
- ✍️ **Improve descriptions** in the catalog so readers know what they're getting.
- 🐛 **Report problems** — broken links, corrupted files, or miscategorized entries — by opening an [issue](https://github.com/tdlmatias/Techie_Books/issues).

### Quick start (add a book via pull request)

1. **Fork** this repository.
2. Add your file to the repo root with a **clear, descriptive filename** (e.g. `Docker-Deep-Dive-Nigel-Poulton.pdf`).
3. Add a row for it in the correct catalog section of this `README.md`.
4. **Commit** and open a **pull request** describing the book and why it belongs here.
5. That's it — a maintainer will review and merge. 🎉

Prefer the web? On **your fork**, use **Add file → Upload files**, drop the book in, commit, and open the pull request from there — no git required.

See **[CONTRIBUTING.md](CONTRIBUTING.md)** for the full guide, including naming conventions and the checklist we use when reviewing.
